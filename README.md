# Indago portal

Private stand-alone React 18 and Vite app for the Indago project. Netlify Database holds the `indago` schema and Better Auth sessions. The portal is separate from the public website. It does not use Supabase.

## Local work

```sh
npm ci
npm run preflight
npm run dev
```

The protected portal is at `/portal/indago` and `/indago` redirects there. `/demo/` is a clearly marked preview with invented records only. It has no database connection, so it can be reviewed while the live data path awaits security review. Both routes send `noindex`; the public website does not link to either.

For local function and database checks, use a local PostgreSQL database as `DATABASE_URL` and run the two migrations in `netlify/database/migrations/` in order. `0001_auth` is the SQL generated by Better Auth 1.7.12; `0002_indago` creates the private schema, roles, policies, immutable source records and audit triggers. `netlify/database/tests/rls.sql` runs inside a rollback transaction after the migrations. Do not run that test on a live database.

On Netlify, `@netlify/database` uses the platform connection. The deployment applies migrations automatically. Function secrets are `BETTER_AUTH_SECRET`, `BETTER_AUTH_URL`, `RESEND_API_KEY` and `RESEND_FROM`. Only invitees in `indago.members` can receive an email link and read records. The member role is `editor` or `viewer`. The function sets the verified Better Auth user ID and a restricted database role within each transaction; Postgres RLS enforces the permissions. There is no browser database key. An administrator adds invite rows directly through an approved database operation after the security review.

## Source import

The three source instruments and approved v1 HTML stay outside Git. `scripts/prepare-import.py` reads both workbooks by sheet name, checks the toolkit document and extracts the v1 Toolkit state. It validates 41 work packages, 6 gates, 140 findings and 31 requests, then writes a private SQL import file. The workbook attachment labels are reversed, so sheet names determine their roles.

```sh
python3 scripts/prepare-import.py plan.xlsx register.xlsx toolkit.docx portal.html import.sql
```

The output contains real client material. Keep it outside the repository and apply it only after Flint's security review and the production backup decision. The first five Client Findings columns and first three Information Requests columns are locked by Postgres. Rollback is `netlify/database/migrations/0002_indago/rollback.sql`, then `0001_auth/rollback.sql`, after exporting data and confirming a restore point. Production changes use a new forward migration; never edit a migration that has already run.

The browser polls every five seconds while visible. Saves use record versions to detect another editor's change. CSV export escapes spreadsheet formulas. The database is the master copy. A two-user live check and private address setup follow the security review. Do not add DNS or load real data from this branch.
