# Indago portal

Private React 18 and Vite app for the Indago project. Netlify Database holds the `indago` schema and Better Auth sessions. The portal runs separately now and is prepared to mount in the Greatstone website later; see [LINKING.md](LINKING.md). It does not use Supabase.

## Local work

```sh
npm ci
npm run preflight
npm run dev
```

Netlify uses `scripts/ignore-build.mjs` before builds on both linked sites. It skips a change only when every file since the cached build is Markdown, under `docs/` or `.github/`, a test file (`*.test.*`), or under `netlify/database/tests/`. A site file, migration, package change, or missing Git comparison builds normally. Netlify treats exit code 0 as skip and 1 as build. This rule also applies to production builds on `main` and does not apply to builds started by build hooks.

Both named Netlify sites have automatic Git deploy previews disabled (`skip_prs=true`). Agents review a draft PR in the GSAM workspace preview. A Netlify draft deploy is permitted only for an open, non-draft PR with the `preview` label or an exact `Preview ready for PR #<number>` task comment from Mikey or John. With a clean checkout at the PR head, an agent reads the scoped `netlify-pat` secret into `NETLIFY_AUTH_TOKEN` and runs `npm exec --yes --package=netlify-cli -- node scripts/deploy-preview.mjs greatstone-indago-preview <number>` (or `greatstone-indago-portal` when that site is the intended target). The token stays in the shell, never in Git or a task comment. The script checks the PR and files, cancels queued or running draft deploys for that same PR and site through the Netlify API, skips non-site-only changes, then makes a Netlify draft deploy. A later push needs a new run; it is not an automatic webhook. Remove the `preview` label after review if no further draft uploads are needed. It cannot cancel a deploy that was not created with this script's PR marker. No production deploy is made by this command.

The protected portal is at `/portal/indago` and `/indago` redirects there. `/demo/` is a clearly marked preview with invented records only. It has no database connection, so it can be reviewed while the live data path awaits security review. Both routes send `noindex`; the public website does not link to either.

`src/indago/` contains the portable screens, model, data adapter and demo fixture. `src/App.jsx` is the stand-alone host. `netlify/functions/indago/` contains the portal request handler; the route adapter and shared Better Auth configuration stay outside that folder. The public website's published footer and legal links replace the stand-alone footer when the module moves.

For local function and database checks, use a local PostgreSQL database as `DATABASE_URL` and run migrations `0001_auth` through `0007_north_star` in order. `0001_auth` is the SQL generated by Better Auth 1.7.12; `0002_indago` creates the private schema, roles, policies, immutable source records and audit triggers. `0003_required_client_locks` guards the fixed client source columns against an incomplete import. `0004_stable_client_locks` keys that guard to the importer's stable sheet IDs, so display-title drift cannot bypass it. Run `netlify/database/tests/rls.sql`, `deliverables.sql` and `north-star.sql` separately after the migrations; each runs inside a rollback transaction. Do not run these tests on a live database.

On Netlify, `@netlify/database` uses the platform connection. The deployment applies migrations automatically. Function secrets are `BETTER_AUTH_SECRET`, `BETTER_AUTH_URL`, `RESEND_API_KEY` and `RESEND_FROM`. By default, only invitees in `indago.members` can receive an email link and read records. The member role is `editor` or `viewer`. The function sets the verified Better Auth user ID and a restricted database role within each transaction; Postgres RLS enforces the permissions. There is no browser database key. An administrator adds invite rows directly through an approved database operation after the security review.

For the approved temporary testing period, `INDAGO_OPEN_ACCESS=true` lets any visitor read and edit through the portal API without signing in. The server sets a transaction-local database flag; the audit trail labels edits `Open access`. Client source fields remain locked. Turn the setting off to restore invited sign-in and 401 responses. Before enabling it, create and record a fresh production Netlify Database snapshot. Migration `0005_open_access` adds the temporary policy path; its rollback restores the original policy and audit functions after the switch is off.

Work-package deliverables use the site-scoped `indago-deliverables` Netlify Blob store and migration `0006_deliverables` for metadata and audit history. Uploads and downloads use 3 MB server-checked chunks to stay within Netlify Function payload limits. Files are served as attachments through the portal function, with the same Viewer and Editor permissions as the Work plan. Soft-deleted files stay in Blob storage and in the audit history. A database snapshot does not contain Blob data: see [the file restore-point procedure](docs/DELIVERABLE-BACKUP.md). Roll back the migration only after exporting the metadata and all Blob chunks; the rollback drops the metadata and file history tables, but leaves Blob chunks intact.

The internal NS-01 North Star instrument uses migration `0007_north_star`: its approved text is seeded in Netlify Database, and each answer is a separate field with an actor, timestamp and full value history. Simultaneous editors use last save per field; changes to different fields never conflict. The API, Evidence requests, history and G2 work-package files are hidden while `INDAGO_OPEN_ACCESS=true`. Named Editors can edit; Viewers can read. The instrument prints to a branded PDF through the browser print dialogue, and the hypotheses register downloads as CSV. Use `netlify/database/tests/north-star.sql` against a local database after applying migrations 0001 to 0007; it runs in a rollback transaction. Before running `0007_north_star/rollback.sql`, export North Star fields, history and linked Evidence request rows. The rollback deletes those records and restores the prior insert policy; signed work-package files remain under the existing deliverables restore procedure.

The invited client interview lives at `/portal/indago/interview`. Migration `0009_client_interviews` stores consent, immutable original answers, separate challenge replies, a corrected summary and a structured G2 draft linked to `IND-NS-001`. Owners see only their own sessions; named facilitators can review and download a plain text export. The route refuses open access. `/demo/interview` uses browser storage and invented preview records only; it never calls the database. The guided path sends no text to an AI service, so expected incremental monthly model usage cost is **£0**. A future AI route needs separate processing approval and a new cost estimate before production. Run `netlify/database/tests/client-interviews.sql` on a disposable local database after migrations 0001 to 0009. Before rolling back 0009, export all interview rows and drafts, then apply `0009_client_interviews/rollback.sql`; rollback permanently deletes those records. The current branch must stay out of client use until invited access is enabled, Flint has checked permissions and John has authorised release.

Migration `0008_facilitators` adds a member flag that defaults to `false`. After Everest confirms the approved Greatstone facilitator email addresses, an administrator can set each named member with `UPDATE indago.members SET facilitator = true WHERE email = lower('approved-address@example.com');`. Keep client members at `false`. Open access always receives the client view. Before rolling back `0008_facilitators`, export any facilitator assignments because the rollback drops the column.

Migration `0014_deep_dive_mcp` adds the Deep Dive MCP at `/api/deep-dive-mcp`: agents read the record and write drafts that a named facilitator approves. Tokens, tools, interview logging and rollback are in [docs/DEEP-DIVE-MCP.md](docs/DEEP-DIVE-MCP.md). Run `netlify/database/tests/deep-dive-mcp.sql` against a local database after all migrations.

## Source import

The three source instruments and approved v1 HTML stay outside Git. `scripts/prepare-import.py` reads both workbooks by sheet name, checks the toolkit document and extracts the v1 Toolkit state. It validates 41 work packages, 6 gates, 140 findings and 31 requests, then writes a private SQL import file. The workbook attachment labels are reversed, so sheet names determine their roles.

```sh
python3 scripts/prepare-import.py plan.xlsx register.xlsx toolkit.docx portal.html import.sql
```

The output contains real client material. Keep it outside the repository and apply it only after Flint's security review and the production backup decision. The first five Client Findings columns and first three Information Requests columns are locked by Postgres. Rollback runs `0004_stable_client_locks/rollback.sql`, then `0003_required_client_locks/rollback.sql`, then `0002_indago/rollback.sql`, then `0001_auth/rollback.sql`, after exporting data and confirming a restore point. Production changes use a new forward migration; never edit a migration that has already run.

The browser polls every five seconds while visible. Saves use record versions to detect another editor's change. CSV export escapes spreadsheet formulas. The database is the master copy. A two-user live check and private address setup follow the security review. Do not add DNS or load real data from this branch.

## Live North Star interviewer (GRE-3641)

Migration `0010_interview_ai` stores the next contextual question so a participant can resume without another model call. Roll back with `0010_interview_ai/rollback.sql`; this removes stored questions, while original answers, separate challenges and submitted drafts remain. The AI route is off unless `INDAGO_AI_INTERVIEW=true`, a server-only `Anthropic_API_Key` (read first, because Netlify fills an unset `ANTHROPIC_API_KEY` with its AI Gateway token) or `ANTHROPIC_API_KEY`, and approved `INDAGO_AI_QUESTION_PROMPT`, `INDAGO_AI_CHALLENGE_PROMPT` and `INDAGO_AI_DRAFT_PROMPT` function settings are all present. The model is `claude-sonnet-5`. Failed or invalid model responses use the guided question, challenge or draft. No key or prompt goes into the browser build. Do not enable this route for client use until the participant notice, named sign-in, security review and release approval are complete.

Migration `0011_interview_ai_choice` stores the participant's choice, made before the first question, between **Start with AI help** and **Continue without AI**. Those two buttons appear only while the AI route is configured. A session started without AI never calls the AI service; its questions, challenges and draft use the guided path. The participant notice is Harbor's wording (GRE-3681 section 5). Its portal retention period, readers and contact are placeholders for John to set before client use. Roll back with `0011_interview_ai_choice/rollback.sql` only together with the code that writes the choice; the rollback removes each session's recorded choice, while answers, challenges and drafts remain.

## Preview sign-in

The Editor and Viewer password route is off by default. It works only on the separate sample-data site at `https://greatstone-indago-preview.netlify.app`, with `INDAGO_TEST_LOGIN_HOST=greatstone-indago-preview.netlify.app`. Public sign-up and password reset remain closed. Normal invited email-link sign-in remains available.

Set distinct 16-character or longer `INDAGO_TEST_EDITOR_PASSWORD` and `INDAGO_TEST_VIEWER_PASSWORD` as values on the separate preview site only. Use `INDAGO_SEED_MODE=1 npm run seed:preview-users` from an authorised shell with the Netlify Database connection and Better Auth secret to create two `.test` accounts and their Editor/Viewer memberships. If the API grants only a read-only database connection, use a token-protected, one-time server function and remove it after seeding. `INDAGO_SEED_MODE` must never be a persistent site setting. Do not put passwords in an issue comment.

Before real data is imported, turn `INDAGO_TEST_LOGIN` off and run `INDAGO_REMOVE_PREVIEW_USERS=1 INDAGO_TEST_LOGIN_HOST=greatstone-indago-preview.netlify.app npm run remove:preview-users` from an authorised shell with the Netlify Database connection (`NETLIFY_DB_URL`, or `DATABASE_URL` for local tests). The command deletes only the two fixed `.test` memberships and Better Auth users in one transaction; their sessions and accounts cascade from the user rows. It refuses to run while preview login is enabled. Verify both accounts and memberships are absent before loading real data.
